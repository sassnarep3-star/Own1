Method

How each row was checked

The evidence standard is deliberately strict and deliberately boring: open the operator page, read the number, write it down with the link. If the page does not state it, the field stays empty.

Evidence standard

  1. One claim, one operator page. A prize, fee or deadline is written only if it appeared on a page the operator controls (a rules page, a game page, a competition page).
  2. No inference. Countdowns such as “8 days to go” are quoted as notes; they are not converted into a date. Totals are not computed from partial prize ladders unless the operator states the total.
  3. Blank beats plausible. If the operator page did not state entry cost, eligibility or a deadline, the field is empty and the row carries a flag saying so.
  4. Third-party claims stay third-party. Legacy prize text from the reference catalogue is displayed only in a column labelled “legacy claim (unverified)”.
  5. Conflicts are published, not resolved. Where one operator page contradicts itself, both values are recorded and the row is flagged.

What was checked, and how

  • DNS resolution was tested for all 223 distinct hostnames in the legacy catalogue on 2026-11-01; six failed and are flagged.
  • 44 rows were verified by opening 41 distinct operator URLs plus supporting rules pages; every one is listed in the table below.
  • Internal links, page structure, dataset schema and the “no inferred values” rules are enforced by tests/validate.mjs, which runs in CI on every push.
  • External deep links were not exhaustively fetched — this environment resolves DNS but cannot fetch arbitrary domains. Reachability of individual URLs is therefore not certified beyond the pages listed below.

Source hierarchy

Tier 1 is the operator's own rules or competition page. Tier 2 is a platform listing that the operator publishes (for example a Devpost or Kaggle event card). Tier 3 is third-party commentary, which is used here only to raise a question, never to answer one. Some verified rows rest on tier 2 evidence and say so in their flags — a prize that only exists on a platform card is weaker evidence than one in a rules document.

Reproducing this

Everything is static. scripts/build-atlas.mjs merges data/verified.json and data/legacy.json into the pages you are reading and into data/atlas-entries.json. Run node scripts/build-atlas.mjs && node tests/validate-atlas.mjs from the repository root to rebuild and re-check. The build is deterministic, so a clean rebuild produces no diff.
