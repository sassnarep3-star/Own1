Second layer

The ledger pass

Another agent session built a complementary pass over the same 206-listing catalogue: every row keeps its catalogue tag, twelve rows carry quoted operator evidence, and a separate audit script computes integrity findings. That work is preserved here rather than replaced.

Two evidence layers, one site. The pages in this section were generated by tools/build_site.py from data/ledger.json and data/verification.json. The pages in the main navigation are generated by scripts/build.mjs from data/verified.json, data/legacy.json and data/atlas-findings.json. Both are published so neither session's work is lost; the two datasets have not been merged into one schema, and that is a known integration gap.

How the two passes differ

  • Catalogue fields. The ledger pass keeps the reference catalogue's own prize text on each row, tagged by free-path and status. This site's pages blank any prize, fee or deadline that was not read from an operator page, and show the catalogue claim only in a column labelled unverified.
  • Depth. The ledger pass re-checked 12 rows with verbatim quotes. This pass verified 44 rows and records prize, entry, deadline, eligibility and work required, with the page read.
  • Findings. The ledger pass computes findings with tools/audit.py; this pass publishes 17 findings with source links on the Flagged for review page.
  • Build. tools/build_site.py owns all.html, verification.html and the other pages listed above. scripts/build.mjs owns index.html, this page and the category pages. Re-running the Python generator will overwrite index.html and category/*.html; see COORDINATION.md before doing that.
