Method

How this was built, and exactly where it stops being reliable.

Three layers: a verbatim mirror of the source catalogue, a deterministic audit over that data, and a separate verification layer that only ever adds a value when an official page was read. The layers are kept apart on purpose so that “the catalogue says” and “we confirmed” can never be confused.

1. Mirror

data/source-data.js is a byte-for-byte copy of the reference site’s assets/data.js (SHA-256 13986a17b8b9aa7b3240232e6138155967cfa9347256faa7b5c7d1565ed73211), taken from karagemop466-tech/FreeMoneyApps. data/ledger.json is that object re-serialised as JSON with no edits and no added fields. If a number is wrong, it is wrong in the same way in both files — which is the point.

2. Audit (mechanical)

python3 tools/audit.py runs 11 literal checks over the mirror: missing official-tier source, dollar figure with no official citation, shared sign-up URL, non-contest rows, ended rows inside the headline free count, “prize not currently knowable” phrases, free labels contradicted by fee language, non-cash currency in payout copy, prose-only prizes, the “added this pass” derivation, and the stale masthead date. It never infers a value. Output: data/audit.json, rendered on Flagged.

3. Verification (official pages only)

data/verification.json holds 12 rows. Each field needs a URL, a verbatim quote and a status; tools/verify_check.py refuses to build if a claim has no quote and is not explicitly marked “not stated”. A contradicted row must declare which catalogue fields are contradicted, and a row whose prize is contradicted cannot carry a verified prize.

4. Priority score (editorial, published)

Total maximum 90 points, normalised to 100. The components:

Evidence counts differently. A prize confirmed on the operator’s own page and a prize confirmed on a page quoting the operator’s terms are both scored 20, because the second is still a verbatim statement of the operator’s rules — but they are never conflated: every row’s evidence kind is printed on the verification page, and the 4 secondary rows are marked as such.

ComponentPointsRule
Free entry, evidenced0–3030 if an operator page confirms free entry; 18 if the catalogue claims free and it was not checked; 8 for “some free events”; 0 for paid-cash or a contradicted fee.
Enterable today0–1515 live, 8 caution, 5 mixed, 0 ended. Reset to 0 if the operator page contradicts availability.
Prize documented0–2020 if a figure was read on a page carrying the operator’s own prize terms — either the operator page itself (8 rows) or a third-party page quoting those terms verbatim (4 rows, labelled secondary-official-terms on the verification page); 10 if the catalogue publishes a dollar figure with no citation; 0 otherwise.

What the score is not: a probability of winning, an expected value, or advice. It cannot price a lottery ticket, and it does not know how many people enter. It exists so that 206 rows can be ordered without hand-waving.

5. What was deliberately not done

  • No currency conversion. A €10,000 prize is shown as €10,000. Converting would invent an exchange rate that no source in this repo supports, so rows are not ranked against each other across currencies.
  • No prize inferred from prose. “Cash rooms advertise prizes up to tens of dollars” does not become $10 in a table.
  • No link-liveness claims. The build shell cannot reach operator domains, so no row is described as “link checked” unless a human-or-agent page read is recorded in verification.json.
  • No removal of a source’s rows. Wrong rows are kept, marked, and flagged — deleting them would hide the fact that they were published.

6. Reproduce it

python3 tools/audit.py          # data/ledger.json -> data/audit.json
python3 tools/verify_check.py   # validates data/verification.json
python3 tools/build_site.py     # renders HTML to the repo root
python3 tools/check_links.py    # internal links + anchors, must be 0 broken

7. Environment limits, stated honestly

Outbound shell network in this sandbox reaches GitHub, npm and PyPI only. Operator sites were therefore read with the agent’s page-fetch tool, and only for the 12 rows on the verification page. Everything else carries the operator’s link and no claim. Two other agent sessions had overlapping claims on this repository when this one began; that is logged in COORDINATION.md.
