Method, provenance and limits

How verification works here

Three rules govern every number on this site: copy the source verbatim, require an official link before a value is shown, and label what was not checked. This page shows exactly what was and was not done, plus how to reproduce it.

How it is handled
The file is vendored unchanged at data/source/ledger.source.js. scripts/ingest.js verifies the checksum, strips the window.LEDGER = prefix and parses the remainder as strict JSON. The JavaScript is never executed.

2. The rules we applied

  1. Copy, never correct. Every source field is carried through verbatim. When the source is internally inconsistent, both facts are recorded and the inconsistency goes on the Flagged page (see I-01).
  2. Official link or no value. A prize or cash-out figure is printed only when the row has a source tagged "official" and the text states an amount. Otherwise the cell is “—” and the row is listed as unverified. 80 rows are blank on this basis.
  3. No inference, no conversion, no summation. £ stays £. "$1K/week + $5K season" is not turned into "$6K". "Up to $10M" is not treated as a $10M prize.
  4. Badge the gap. A row is "Live-checked" only if its own URL was fetched this pass. Everything else says so, and the full not-checked list is published.
  5. Publish the problems. Anything odd becomes a numbered flag with evidence and links, not a silent edit.

4. What was actually fetched

13 URLs were retrieved on 1 Nov 2026 — at least one per category, weighted towards rows with the highest stakes and the oddest claims. The full log, including what each page confirmed and what it did not, is the last table on the Flagged for review page.

Why not all 220? The build environment had no general outbound internet; each page had to be fetched individually through a page-fetch tool. A full crawl is roughly 400 requests across 206 domains and was out of scope for this pass. That limit is stated on every page rather than papered over.

5. Reproduce this build

Everything is generated from the JSON in data/:

  • node scripts/ingest.js — verify the source checksum and write data/ledger.json
  • node scripts/verify.js — audit every row, write data/verification.json and data/irregularities.json
  • node scripts/build.js — render the site
  • node scripts/checklinks.js — confirm every internal link resolves and every row is published exactly once
  • node scripts/render-docs.js — regenerate docs/EXECUTIVE_SUMMARY.md from the same content as this site

To extend verification, add entries to data/live-checks.json and re-run verify.js then build.js: rows whose URLs appear there upgrade themselves to "Live-checked" automatically.

6. Limitations you should assume

  • Prize claims are 74 days old and can change without notice.
  • Third-party text — the source ledger — is the origin of every row's description; we verify the operator link, not every sentence the source wrote.
  • No odds, entrant counts, effort estimates or expected-value figures exist in the data, so none are shown anywhere on this site.
  • Tax: the “US prizes of $600+ normally require a W-9” line is the source dataset's generalisation, not a rule. Reporting depends on the type of income and your circumstances — see I-21 and the IRS pages linked there. Nothing here is tax advice.
  • Links on operator sites rot. The "link error" badge is one observation, not a permanent state.
